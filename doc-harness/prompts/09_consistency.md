# Phase I09 — Cross-Document Consistency(증분)

부분 갱신 때문에 문서끼리 **모순**이 생기지 않았는지 확인한다. 아래 "갱신된 문서"와 그 문서가 참조하거나 같은 대상을 다루는 "갱신되지 않은 문서"를 비교한다.

## 찾을 것(모순만)

- 기능 문서는 새 구조를 말하는데 아키텍처 문서는 옛 구조를 말한다.
- API 문서의 응답과 데이터 모델의 DTO가 다르다.
- 같은 엔드포인트·엔티티·컴포넌트·설정 키가 문서마다 다른 이름·경로·동작으로 적혀 있다.
- 시퀀스 다이어그램의 순서가 다른 문서의 흐름 설명과 다르다.
- 제거된 기능을 아직 현재 기능처럼 언급한다.

## 규칙

- 모순이 있으면 코드를 Read해 **어느 쪽이 맞는지** 확인하고, 틀린 쪽 문서를 `issues[].document`로, `description`에 "무엇이 무엇과 모순되며 코드는 어떤가"를 적는다. `section`에 앵커 id.
- 모순이 아닌 표현 차이·상세도 차이는 지적하지 않는다.
- 없으면 `issues`는 빈 배열, `summary`에 "모순 없음".
