## 작성 규칙

- **두괄식.** 각 섹션은 결론 문장으로 시작한다. 장황한 설명보다 표와 목록.
- 워크스페이스 산출물(아래 입력)이 1차 재료다. 산출물에 없는 사실을 쓰려면 코드를 Read해 확인하고 evidence 섹션에 근거를 남긴다. 확인 못 하면 쓰지 않는다.
- 파일 경로·클래스·엔드포인트·설정 키·명령은 **실존하는 것만**. 존재하지 않는 API·클래스·명령을 만들지 않는다.
- 다른 생성 문서 링크는 상대 경로(`08_API.md`, `features/F001_SLUG.md`). 기존 손글씨 문서(`docs/*.md`)는 링크하지 않는다.
- 본문은 한국어. 식별자는 원문. 마크다운 표는 `|`로, 셀 안에 줄바꿈 금지.
- 다이어그램이 필요한 섹션만 `diagrams`에 넣는다(id는 지시된 것, `nodes`에 실제 코드 경로, style 금지). 섹션 본문에는 mermaid를 직접 쓰지 않는다 — 하네스가 diagrams를 렌더한다.
- 섹션 `id`는 아래 골격의 id를 그대로 쓴다. 골격에 없는 섹션을 추가하려면 `extra-<이름>` 형식.
