## 설계 (2026-09-20)

이전 설계(PARA 노트앱)를 폐기하고 **보안 최우선 기술 블로그**로 방향을 바꿨습니다. 사용자가 확정한 것: 보안이 최우선(선택이 갈리면 더 엄격한 쪽), 글은 상태 없음(저장 = 즉시 공개), 공개 페이지는 서버 렌더링·React는 관리 에디터에만, 쓰기 권한은 IP 허용 목록 **AND** 비밀번호 세션.

초안을 OpenAI Codex CLI로 교차 검토해 23건을 받았고, 수용분과 의견이 갈린 4건의 근거를 스펙 2.6절에 남겼습니다.

## 1단계 — 접근 제어와 관리 API

도메인 모델·DB 제약(slug 형식·유일·불변, `SeriesOrder` CHECK), 호스트·IP·CSRF 3겹 접근 제어, 비밀번호 로그인과 세션 폐기(절대 수명·해시 지문·epoch), 글·시리즈·태그 관리 API.

구현 중 계획이 틀린 것으로 드러난 것:

- **로그인 속도 제한기가 원시 경로 문자열로 파티션을 골랐습니다** — 끝에 슬래시를 붙인 `/api/auth/login/`으로 우회됐습니다. 엔드포인트 메타데이터로 고르도록 바꿨습니다.
- **IP 검사가 속도 제한보다 뒤에 있었습니다** — 허용 IP 밖의 요청이 로그인 전역 한도를 소진해 작성자를 잠글 수 있었습니다. 순서를 뒤집었습니다.
- `appsettings.json`의 빈 문자열 기본값이 `??` 널 병합을 통과해 "설정 없음"을 잡지 못했습니다.

## 2A단계 — 마크다운과 첨부

Markdig 파이프라인(raw HTML 비활성 → URL 정책 → 서버 측 강조 → HTML 허용 목록 정제), `POST /api/preview`, 이미지 첨부(시그니처 판정·메타데이터 제거·내용 주소 저장).

- **가장 큰 교훈: 계획을 그대로 옮긴 코드는 매번 통과했지만, 계획 자체가 틀려 있었습니다.** 측정하지 않고 쓴 문장이 결함의 원천이었습니다(계획 결함 16건).
- **Markdig 파서 자체가 초선형 비용**을 냅니다 — 적대적 200KB 입력에서 인라인 약 8.5초, 블록 약 6.6초(동기·취소 불가). 강조기에 시간 예산을 걸어도 파서는 남습니다. → 2B의 렌더 게이트·캐시로 덮었습니다.
- 메타데이터 제거기를 **기본 거부**(허용한 블록만, 모양까지 검사)로 다시 설계했습니다. 디코딩하지 않으므로 못 막는 잔여 표면 5종은 스펙에 명시하고 크기 상한·`nosniff`·sandbox CSP로 완화했습니다.
- 첫 Linux CI 실행에서 **절대 시간 상한을 둔 테스트가 깨졌습니다**(로컬 0.8초 → CI 7.2초). 이후 시간은 `TimeProvider`로 주입하고 비율로 단언합니다.

## 2B단계 — 공개 사이트

공개 Razor 페이지(목록·글·태그·시리즈·검색), Atom·sitemap·robots, 보안 헤더, 호스트 필터, 공개·검색 속도 제한, 읽기 전용 DB 연결(`statement_timeout`), 렌더 게이트와 캐시, 첨부 정합성(advisory lock·고아 청소).

- **최종 리뷰에서 실제 Production 호스트를 HTTPS로 직접 찔러, 인메모리 TestServer 579개가 놓친 결함 3건을 찾았습니다.**
  - 호스트 필터의 400이 프레임워크 HTML 본문을 실어 보냈다(그 응답은 앱 미들웨어 바깥이라 CSP·`nosniff`가 없다) → 본문을 껐다.
  - `publish` 출력의 `wwwroot`에 `.gz`·`.br` 사본이 생겨 `/css/site.css.gz`가 200이었다 → `CompressionEnabled=false`.
  - 경로 값이 공백뿐일 때(`/tags/%20`) MVC 바인딩이 `string` 매개변수를 **null**로 넣어 NRE → 500 → 핸들러를 `string?`로 받고 첫 줄에서 404.
- 그 밖에 계획 결함 23건, 내린 판정 28건. 이때부터 "테스트 스위트가 통과했다"와 "실제 호스트가 그렇게 응답한다"를 다른 명제로 취급합니다.
- 로컬 프로브가 평문 HTTP에서 변조된 응답을 보여 준 일이 있어(이 기계의 광고 차단기가 HTML과 CSP 헤더를 다시 씀) **실제 호스트 프로브는 HTTPS로만** 한다는 규칙이 생겼습니다.

## 3단계 — 관리 에디터 SPA

React 19 + Vite + CodeMirror 6로 글·시리즈·태그·첨부 관리 화면, sandbox iframe 미리보기, 임시본, 409 비교 화면. 실제 백엔드를 띄우는 Playwright E2E 8개와 CI 잡 둘(`web`·`web-e2e`)을 붙였습니다.

- **보안 통제 자체가 결함의 원천이었습니다.** 소스 가드(금지 패턴 검사)가 주석 제거 단계에서 **실제 코드를 삼켜** 그 구간의 위반을 놓쳤습니다. 세 라운드에 걸쳐 고쳤고, 그 과정에서 내가 내린 판정 하나(R5: 줄 주석을 먼저 지운다)가 틀려 뒤집혔습니다. 최종 형태는 TypeScript 파서로 리프 토큰의 trivia만 지우고, 지운 위치가 어떤 토큰 안에도 없다는 것을 독립 파싱으로 교차 검증합니다.
- 테스트 하네스의 "표에 없는 호출은 실패한다"는 단언이 **거짓**이었습니다(그 경로가 실제로 실패시키지 않았습니다).
- 최종 리뷰가 실제 호스트에서 5건을 더 찾았습니다: 디바운스 창 안의 입력이 세션 만료·화면 이탈 때 사라짐, 비밀번호가 mutation 변수로 캐시에 남음, SPA 라우트 `/attachments`가 개발 프록시의 접두사 매칭 때문에 백엔드로 끌려감, 보통 속도의 글쓰기로도 미리보기가 429에 닿음, 라우트 오류 경계 없음.
- 브라우저 차이도 실측으로 확정했습니다: Firefox는 `about:srcdoc` 문서의 CSP `'self'`를 부모 출처로 보지 않아 미리보기의 CSS·이미지가 전부 차단됩니다 → 출처를 명시합니다.

## 4단계 — 배포 (브랜치 완료, PR 대기)

브랜치 `feature/blog-deploy`. 계획을 쓰기 전에 저장소 밖 복사본에서 이미지·compose·Caddyfile·백업 복원·스택 E2E를 **실제로 띄워 16가지를 측정**하고(S1~S16), 그 결과로 계획을 썼습니다. 그럼에도 리뷰가 그 위에서 더 찾아냈습니다.

지금까지: 공개 조회 전용 DB 롤과 시작 검증 강화·헬스체크 CLI(완료), Caddyfile과 이미지 둘, compose·DB 롤 초기화·스택 스모크. 남은 것은 백업/복원·운영 문서, 스택 대상 브라우저 E2E와 CI 잡, 문서 반영입니다.

리뷰가 잡은 대표적인 것:

- `REVOKE … FROM {role}`은 **`PUBLIC` 의사 롤에 준 권한을 회수하지 못합니다** — 그 경로로 공개 롤이 `AdminState`를 읽고 썼습니다(실측).
- 스키마 전체를 대상으로 회수하면 **관리 롤이 비 슈퍼유저인 운영 형태에서 남의 소유 테이블 하나 때문에 기동이 막힙니다**. 테스트 하네스가 슈퍼유저로 접속하기 때문에 이 결함은 초록불로 지나갔습니다 → 비 슈퍼유저 소유자 롤로 도는 회귀 테스트를 추가했습니다.
- Caddy의 오류 응답 경로는 라우트의 지연 응답 래퍼를 거치지 않아 `Server` 헤더 삭제가 무효였습니다(405·413·502에서 노출).
- Caddyfile 헤더를 지키는 가드가 **위치 단언**이라, 헤더 블록을 다른 위치로 옮기는 변경을 잡지 못했습니다(테스트는 5/5 통과하는데 실제 응답의 보안 헤더 7개가 전부 사라짐).
- 스모크의 DB 롤 검사가 `127.0.0.1`로 붙어 pg_hba의 `trust` 줄을 타는 바람에 **비밀번호를 전혀 검증하지 않았습니다**.

측정으로 확정한 좋은 소식도 있습니다: ACME HTTP-01은 명시 `http://` 블록·IP 허용 목록과 공존합니다(실제 발급으로 증명). 자세한 내용은 [배포 구성](deployment.md).

## 이 저장소가 일하는 방식

작업은 **브레인스토밍 → 계획 → 실행 → 리뷰 → 보고서** 순서로 돌고, 각 단계가 파일로 남습니다.

- 계획은 `docs/superpowers/plans/`에, 실행 결과 보고서는 `plan/`에 둡니다. 보고서에는 **"질문 없이 내린 판정"** 표(결정 / 이유 / 틀렸을 때의 비용)가 들어갑니다.
- 계획대로 구현한 뒤 **리뷰어가 계획 자체를 의심**합니다("계획 코드가 틀렸을 수 있다 — 직접 공격하고 측정하라"). 실제로 매 단계에서 계획 결함이 나왔습니다.
- 리뷰어는 저장소 밖 복사본에서만 측정합니다(작업 트리를 오염시키지 않기 위해).
- 새 테스트는 **사보타주로 실패를 확인**합니다 → [테스트](testing.md).
- 설계 국면에서는 OpenAI Codex CLI를 read-only 교차 검증자로 부릅니다 → [개발 하네스](harness.md).
